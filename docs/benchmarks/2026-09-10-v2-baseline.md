# PDF Cleaner V2 — Task 10 Regression / Benchmark Baseline

**Benchmark date:** 2026-09-12  
**Execution branch:** `refactor/pdf-cleaner-v2`  
**Environment:** Linux 6.18 x86_64, Python 3.13.5, 5 logical CPUs, 5.81 GiB RAM  
**Harness:** `scripts/benchmark_v2.py`  

## Scope and gate

This benchmark validates the Task 10 hardening against the four owner-provided inputs. The owner PDFs are local-only and are **not committed**. Each case runs V2 and the corresponding legacy compatibility path in a fresh subprocess while the parent samples RSS for the complete process tree.

V2 quality gates were not relaxed:

- `max_outside_change_ratio = 0.08`
- `max_watermark_residual_score = 0.08`
- no legacy fallback allowed for the V2 benchmark
- OCR remains optional; all four V2 runs used `0` OCR calls

Legacy output is timed and measured for peak RAM / output size, but the legacy benchmark path does **not** run V2 QC. Therefore legacy residual, outside-change and `qc_ok` are recorded as **N/A**, not inferred.

## Quality / visual regression observations

Automated V2 QC passes on all four runs. The two raster TaiLieuOnThi inputs are now guarded by a residual metric in addition to outside-mask change, so an obvious watermark ghost cannot pass only because non-watermark content was preserved.

Manual spot-checks of the final benchmark outputs were also performed on the areas that previously exposed the defect:

- `day1`, page 2: the diagonal TaiLieuOnThi watermark through the true/false (`Đ/S`) table is no longer visibly present; the `Đ/S` columns, circles, colored cells and table rules remain intact.
- `hoa`, pages 1 and 9: header/footer/diagonal watermark traces are not visibly apparent in the checked areas; chemistry equations, subscripts/superscripts, answer coloring and layout remain readable.
- `dao` remains on the structural `stream_remove` fast path, with no page rasterization.

These manual observations supplement, but do not replace, the numeric QC gate.

## Hardening implemented during Task 10

1. Structural/vector and hybrid E2E regressions now account for the intended watermark region instead of treating target removal as outside-mask loss.
2. Raster consensus samples are bounded rather than materializing full native page images for model learning.
3. TaiLieuOnThi raster documents use a signature-specific **TDM-guided** repair primitive based on the proven original TDM V7 cleanup, while routing remains automatic and representation/signature-based rather than subject-selected.
4. TDM-guided work is isolated in short-lived workers to contain native state / memory accumulation.
5. Only trusted header/footer/diagonal cleanup pixels are transferred back to the native page image; pixels outside trusted watermark zones are preserved.
6. Unsafe raster documents with rotation, annotations, unrelated links, text layers or non-conservative page-image structure are rejected instead of silently losing structure.
7. V2 QC now consumes `watermark_residual_score` and fails when residual exceeds `0.08`, even when outside-mask change is low.
8. The regression suite retains the output-size guard: cleaned raster output may not explode beyond 4× the source fixture size.

## Decision on legacy engines

**Decision: keep all legacy engines as compatibility fallbacks. Do not delete or deprecate any legacy engine in Task 10.**

Evidence does not justify removal yet:

- V2 is substantially faster and dramatically lower-RAM on the structural `dao` case while preserving vector structure.
- V2 raster TaiLieuOnThi outputs now satisfy the stronger quality gate and use less peak RAM than the measured legacy runs, but they are currently slower on the two `day` runs and especially on `hoa`.
- Legacy quality metrics are not automatically comparable because the legacy benchmark path does not produce the V2 residual/outside-change QC metrics.

Deletion or deprecation therefore requires a separate approved change after broader corpus coverage and repeat-run performance work.
